# Руководство по работе с репозиторием

## Структура проекта

EduFlow — приложение на FastAPI с воркером Celery для расшифровки лекций и обработки текста с помощью ИИ. Точка входа `app/main.py` запускает API и отдаёт веб-интерфейс из `app/web/`. JavaScript, CSS и изображения находятся в `app/web/assets/`. Размещайте обработчики маршрутов в `app/api/`, а логику обработки в `app/services/`. Модели SQLAlchemy находятся в `app/models.py`, схемы запросов и ответов в `app/schemas.py`, миграции в `alembic/versions/`. Тесты и общие фикстуры находятся в `tests/`.

## Сборка, запуск и проверки

- `python scripts/setup_env.py` при первой настройке создаёт локальный `.env` и генерирует секреты. Храните `.env` вне Git. Для обработки лекций задайте `AI_MODEL` и API-ключ выбранного провайдера.
- `docker compose up --build` собирает образы и запускает API, воркер, PostgreSQL, Redis и Mailpit. Compose применяет миграции перед запуском API и воркера. Приложение доступно по адресу `http://localhost:8000`, документация API — по пути `/docs`.
- `python -m pip install -e '.[dev]'` устанавливает приложение и инструменты разработки в активное виртуальное окружение. Используйте Python 3.11 или новее. В CI используется Python 3.12.
- `pytest -q` запускает все тесты. При изменении моделей базы данных выполните `alembic upgrade head` и `alembic check` на отдельной временной базе PostgreSQL.

## Стиль кода и именование

Используйте отступы в четыре пробела, `snake_case` для модулей и функций и `PascalCase` для классов. Ограничивайте длину строки 100 символами согласно настройкам Ruff и добавляйте аннотации типов в код приложения. Перед открытием PR выполните `ruff check .`, `ruff format --check .` и `mypy app`.

## Тестирование

Используйте pytest и pytest-asyncio. Называйте файлы `test_<module>.py`, а функции — `test_<behavior>`. Используйте общие фикстуры SQLite и подменяйте внешние сервисы моками. Для локального запуска интеграционных тестов из CI укажите адреса временных экземпляров PostgreSQL и Redis в `TEST_DATABASE_URL` и `TEST_REDIS_URL`. Минимальный процент покрытия в CI не задан.

## Коммиты и пул-реквесты

Оформляйте сообщения коммитов в принятом формате `type(scope)`, например `feat(backend): add lecture processing API`. Указывайте область изменения, когда это помогает понять коммит. Открывайте PR из веток `feature/…` или `bugfix/…` в `develop`. Кратко опишите изменение, приложите ссылку на задачу при её наличии, перечислите шаги проверки и результаты. Добавьте скриншоты, если изменения видны пользователю. Перед слиянием убедитесь, что CI прошёл, и уточните у команды, какие согласования нужны по ревью кода, QA и дизайну.
